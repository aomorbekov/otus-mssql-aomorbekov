# otus-mssql-aomorbekov
# Проект: База данных для ИТ-Мониторинга (monitoringdb)

## 1. Описание проекта
Транзакционная база данных (oltp) для ИТ-отдела, объединяющая инвентаризацию ИТ-инфраструктуры (cmdb) и систему реагирования на инциденты (itsm). База спроектирована в 3-й нормальной форме (3нф).

## 2. Структура таблиц (12 таблиц)

### Блок 1: Справочники (dictionaries)
Обеспечивают ссылочную целостность и защиту от аномалий ввода.
* `roles` — роли пользователей системы.
* `statuses` — статусы жизненного цикла инцидента.
* `severities` — уровни критичности инцидентов.
* `metrictypes` — типы собираемых метрик (cpu, ram, диск) и их единицы измерения.
* `operatingsystems` — справочник операционных систем серверов.

### Блок 2: Инвентаризация (cmdb)
* `users` — учетные записи сотрудников с привязкой к ролям.
* `servers` — реестр серверов, хранит hostname, ip-адрес, среду (prod, dev) и тип ос.
* `services` — службы и порты, запущенные на серверах.

### Блок 3: Транзакционное ядро (метрики и инциденты)
* `servermetrics` — высоконагруженная таблица для хранения потоковых метрик. Секционирована (partitioning) по месяцам.
* `servermetrics_archive` — архивная таблица-клон. Структурно идентична таблице `servermetrics` и привязана к той же схеме секционирования `ps_metrics_monthly`. Используется как буфер (target) для мгновенной метаданной операции `switch partition`. Это позволяет отключать старые секции метрик за миллисекунды без записи в лог транзакций (minimal logging) и блокировок основной таблицы, после чего архив безопасно очищается (`truncate table`).
* `incidents` — журнал регистрации инцидентов (аварий) с привязкой к серверу, сервису и фиксацией времени.
* `incidentcomments` — история комментариев пользователей по ходу решения инцидента.

## 3. Программируемые объекты (бизнес-логика)

### Секционирование (partitioning)
Обеспечивает распределение данных высоконагруженных таблиц для оптимизации операций ввода-вывода (i/o) и быстрого обслуживания.
* `pf_metrics_monthly` — функция секционирования (partition function). Распределяет данные по диапазонам дат с шагом в 1 месяц.
* `ps_metrics_monthly` — схема секционирования (partition scheme). Привязывает секции к файловой группе `[primary]`.

### Представления (views)
* `vw_activeincidents` — выводит список нерешенных инцидентов с автоматическим расчетом времени простоя (downtime).
* `vw_serverhealth` — агрегирует состояние серверов, подсчитывая количество новых и активных инцидентов по каждому узлу.

### Функции (functions)
* `fn_getincidentduration` — скалярная функция для расчета длительности инцидента в минутах.

### Хранимые процедуры (stored procedures)
* `sp_addservermetric` — запись новой метрики от сервера.
* `sp_createincident` — регистрация новой аварии.
* `sp_updateincidentstatus` — изменение статуса инцидента (смена на "Решен" автоматически фиксирует время `resolvedat`). Обернуто в явную транзакцию.
* `sp_autoresolveincident` — системная процедура для автоматического закрытия инцидента.
* `sp_purgeoldmetrics` — обслуживающая процедура. Выполняет `switch partition` для мгновенного переноса устаревших метрик в архивную таблицу с последующей очисткой.

### Триггеры (triggers)
* `trg_incidentstatusguard` — after update триггер на таблице `incidents`. Блокирует транзакцию и выдает ошибку при попытке перевести решенный/закрытый инцидент в статус "Новый".

## 4. Безопасность
Создана специальная роль `monitoringapprole`. Прямой доступ к таблицам (insert, update, delete, select) запрещен. Приложение может только выполнять процедуры (`grant execute`) и читать представления (`grant select`).
